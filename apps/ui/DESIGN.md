# Proof — the WordPress Studio Design System

The design system for `apps/ui` (the agentic Studio UI). Its whole job is to stop
guesswork: **every token and component here is proven to exist** — if it isn't in this
file, don't use it. Read this before any UI or CSS change in `apps/ui`.

Proof is a thin layer over the WordPress Design System: [`@wordpress/ui`](https://www.npmjs.com/package/@wordpress/ui)
for components, [`@wordpress/theme`](https://www.npmjs.com/package/@wordpress/theme)
for the theming runtime and `--wpds-*` tokens, and [`@wordpress/icons`](https://www.npmjs.com/package/@wordpress/icons)
for iconography.

---

## 1. How to use this file

- **Before touching UI/CSS in `apps/ui`, read this.** It is the source of truth for
  which tokens and component idioms exist in this app.
- **The token catalog (§5) is autogenerated** from the installed `@wordpress/theme`
  package. Never hand-edit that block. After bumping `@wordpress/theme` (or any time it
  looks stale), regenerate it:
  ```bash
  cd apps/ui && npm run gen:design-tokens
  ```
- **If a token isn't in §5, it doesn't exist.** Do not invent a name by analogy — the
  grammar is only *partially* populated (see §4). Verify, then use.

## 2. The stack & the two-library rule

| Layer | Package | Role |
| --- | --- | --- |
| Components | **`@wordpress/ui`** (v0.14) | The component library. Use this. Built on `@base-ui/react`. |
| Theming | **`@wordpress/theme`** (v0.14) | `ThemeProvider` + every `--wpds-*` token; drives light/dark + density. |
| Icons | **`@wordpress/icons`** | Iconography (`<Icon icon={…} />`). |
| Components (legacy) | **`@wordpress/components`** (v34) | ⚠️ Legacy. Do **not** add new usages. Migration away is planned. |

**The two-library rule:** default to `@wordpress/ui`. `@wordpress/components` is the old
WordPress admin library; it still appears in a handful of files (form controls, a
`DropdownMenu`, the classic `Tabs`) but is on its way out. Don't reach for it for new
work — if `@wordpress/ui` lacks something, wrap a `@base-ui/react` primitive locally
(that's what `components/menu/` and `components/spinner/` already do) rather than pulling
in the legacy library.

**`--wpds-*` is the only color source.** Never use `--color-frame-*` here — those belong
to `apps/studio` (the legacy renderer). Never hardcode a hex; the token handles dark mode.

### The ThemeProvider / private-API setup

`@wordpress/theme`'s `ThemeProvider` is a **private API**, reached via `unlock()`
(`apps/ui/src/lock-unlock.ts`) and applied once in
[`app-providers.tsx`](src/app/app-providers.tsx) as
`<ThemeProvider isRoot density="compact">`. That single provider is what injects all the
`--wpds-*` variables and resolves them per color scheme. You don't set it up per
component — you just consume the tokens.

## 3. Rules for the agent (do / don't)

1. **Do** consume colors only via `--wpds-color-*`. **Don't** use `--color-frame-*`
   (wrong app) or raw hex values.
2. **Verify a token exists in §5 before using it.** The grammar is partial — plausible
   names like `--wpds-color-fg-content-neutral-strong` do **not** exist even though
   `--wpds-color-fg-interactive-neutral-strong` does.
3. **Button `variant` is `minimal | solid | outline | unstyled`** — never the classic WP
   `primary/secondary/tertiary`.
4. **There is no bold.** Font weight is only `regular` or `medium`; even headings render
   `regular`.
5. **The type scale is token-named and caps at `2xl`** (`xs`…`2xl`). No numeric font sizes.
6. **Use `cursor: var(--wpds-cursor-control)`**, not `cursor: pointer`, for interactive
   elements.
7. **Dark mode is driven by `ThemeProvider` + the saved-preference toggle**
   ([`use-color-scheme.ts`](src/hooks/use-color-scheme.ts)). Don't read
   `prefers-color-scheme` in JS to decide theme — read it only in CSS, and only when a
   token can't express what you need. Always test changes in **both** schemes.
8. **Don't add `@wordpress/components` imports.** Prefer `@wordpress/ui`; wrap a
   `@base-ui/react` primitive locally if needed.
9. **Match the existing CSS-module convention** (folder-per-component + `style.module.css`,
   tokens for every value). See [`components/app-message-cards/`](src/components/app-message-cards/)
   for the house style.

## 4. The token grammar (why you keep guessing wrong)

Color tokens follow a four-part path, but **not every combination is defined** — that
partial-ness is the #1 source of invented names. Always confirm against §5.

```
--wpds-color-{layer}-{role}-{tone}[-modifier][-state]
```

- **layer** — `bg` (fills) · `fg` (text & icons) · `stroke` (borders & rings)
- **role** —
  - under `fg`: `content` (static text/icons) vs `interactive` (actionable — links, button labels)
  - under `bg`: `surface` (static panels) · `interactive` (buttons/hover) · `track`/`thumb` (sliders)
  - under `stroke`: `surface` · `interactive` · `focus`
- **tone** — `neutral · brand · error · success · warning · caution · info`
- **modifier** — `weak` (lower emphasis) / `strong` (higher emphasis), or omitted for the base
- **state** — `-active` (hover/focus/pressed) / `-disabled`

Everyday picks:
- Body text → `--wpds-color-fg-content-neutral`; secondary text → `…-neutral-weak`
- A link / actionable label → `--wpds-color-fg-interactive-brand`
- A static panel background → `--wpds-color-bg-surface-neutral`
- A hover fill on a control → `--wpds-color-bg-interactive-neutral-weak-active`
- A focus ring → `--wpds-color-stroke-focus-brand`

The non-color families (`dimension`, `typography`, `border`, `elevation`, `motion`,
`cursor`) are theme-independent and use a simple `xs…3xl` / named scale — see §5.

## 6. Component idioms

The `@wordpress/ui` surface actually available (top-level exports): `Button`,
`IconButton`, `Icon`, `Link`, `Text`, `Badge`, `Stack`, `VisuallyHidden`, and the
compound/namespaced components `Card`, `Collapsible`, `CollapsibleCard`, `Dialog`,
`AlertDialog`, `Drawer`, `EmptyState`, `Notice`, `Popover`, `Tabs`, `Tooltip`, plus the
form family (`InputControl`, `SelectControl`, and `Field`/`Fieldset`/`Input`/`Textarea`/
`Select`/`Autocomplete` primitives). Note: **no `Spinner`, `Checkbox`, or toggle/switch**
exports — those are local components or `@base-ui/react` wrappers.

- **Button** — `variant="minimal | solid | outline | unstyled"`. `solid` for the primary
  action, `outline` for secondary, `minimal` for low-emphasis/toolbar actions, `unstyled`
  when you need button semantics with fully custom styling.
- **IconButton** — icon-only actions; pair with a `Tooltip` for the label.
- **Icon** — `<Icon icon={ chevronDown } />` with glyphs from `@wordpress/icons`. Icons
  are auto-shrunk to 16px under compact density (see the override in §5 / `index.css`);
  add `data-keep-size` to opt an illustration out.
- **Tooltip** — requires the app-level `Tooltip.Provider` (already mounted in
  `app-providers.tsx`).
- **Dialog / AlertDialog / Drawer / Popover / Notice / Card / EmptyState / Tabs** —
  namespaced compound components (`Dialog.Root`, `Dialog.Title`, …). Portalled surfaces
  stack via the `--wp-ui-*-z-index` overrides in §5.
- **Forms** — prefer `@wordpress/ui` form controls (`InputControl`, `SelectControl`, and
  the `Field`/`Fieldset` primitives). `DataForm` + `useFormValidity` back the richer forms.
- **Local wrappers** — where `@wordpress/ui` has no equivalent, this app wraps
  `@base-ui/react`: [`components/menu/`](src/components/menu/) (menus & context menus),
  [`components/spinner/`](src/components/spinner/). Reuse these instead of the legacy library.
- **Routing** — code-based routes via `createRoute` / `useNavigate` from `@wordpress/ui`
  (see `README.md` → Routing).
