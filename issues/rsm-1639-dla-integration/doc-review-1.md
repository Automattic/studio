## Verdict: approved

## Summary

T9 (`apps/cli/README.md`) and T10 (`docs/design-docs/cli.md`) document the DLA integration accurately, completely, and consistently with the surrounding files. T9 stays user-facing and slots cleanly into the existing README structure (ToC entry added, section placed between "Studio Code" and "Import and export", same tone as neighbouring sections), and T10 is engineer-facing architecture documentation that matches the existing `cli.md` structure (placed at the bottom alongside the existing top-level architecture sections, code blocks where they're load-bearing, no speculation beyond what the code does). Every concrete claim cross-checks against the as-built code: the file paths (`apps/cli/ai/dla/`, `apps/cli/ai/dla-permissions.ts`, `scripts/download-data-liberation-agent.ts`, `apps/cli/ai/agent.ts`) all exist; the function name (`buildDlaCanUseTool`) matches the export in `dla-permissions.ts`; the per-tool policy in T10 matches the `READ_ONLY_DLA_TOOLS` and `ASK_ONCE_DLA_TOOLS` sets in `dla-permissions.ts`; the spawn shape (`process.execPath`, absolute path to `mcp-server.js`, no `cwd`, `STUDIO_WPCOM_TOKEN` forwarding) matches `agent.ts:129-138`; the `existsSync` gate is correctly attributed to `startAiAgent` in `agent.ts`; the `STUDIO_REFRESH_DLA=1` / `--update` opt-in matches the script's actual flag handling; the relative link from `apps/cli/README.md` to `../../docs/design-docs/cli.md` resolves correctly.

Both files keep CLI scope only — neither mentions Electron-side state, IPC handlers, or `apps/studio/` paths in a way that would conflate behaviours, and the only Electron reference (T10's note that `process.execPath` ensures DLA runs under "the same Electron-bundled Node runtime the host CLI is using") is a correct factual claim about the runtime, not a behaviour conflation. T9's `GH_PAT` note correctly directs users to T10 for details, T10 cross-links the canonical `research-report.md` for trade-off rationale, and T10 explicitly tags the per-tool policy as living in `apps/cli/ai/dla-permissions.ts` so future maintainers can find the source. Approving with no must-fix issues; minor non-blocking observations are recorded below for tracking.

## Non-blocking observations

These do not warrant rejection. Recording them here so they can be picked up in a follow-up if the team wants:

- **T10 lumps `liberate_setup` and `liberate_import` manifests together.** The "Handoff contract: `delegate: true`" section says "DLA's `liberate_setup` and `liberate_import` MCP tools accept a `delegate: true` flag … it returns a structured manifest of artifact paths (`{ wxrFile, outputDir, mediaDir, productsCsv, redirectMap, importAuthors }`)". The artifact-paths manifest is specifically the `liberate_import` shape (per `wave-1-dla-inventory.md` lines 89-90); `liberate_setup` returns a different "manifest of requirements" (target WP URL, app password, etc.). The narrative still correctly describes the resulting flow, but the manifest example printed is `_import`-specific. Minor accuracy nit, not a misdirection.
- **Pre-existing typo in `apps/cli/README.md:94`.** The "Delete, lis,t or resume" line above the new section has a stray comma in "list". Pre-dates this PR (not introduced by T9) — flagging because it's adjacent. Out of scope for this review.
- **T9's Note block uses `> **Note:**` admonition.** The existing README does not use blockquote admonitions elsewhere. Stylistically slightly inconsistent with the surrounding doc; the warning is load-bearing enough that the visual emphasis is justified, but a future README pass could homogenise admonitions.
- **T10's permission-scoping section says "Headless / no `onAskUser`. Ask-once tools deny rather than auto-approve…"** — accurate. Worth noting that this matches the TODO comment in `dla-permissions.ts:183-184` flagging a future non-interactive opt-in; T10 doesn't mention the TODO (which is fine — the doc is current-state, not a roadmap).
- **T10 SDK type cite.** T10 says "the Anthropic Agent SDK's `McpStdioServerConfig` exposes `{ type, command, args, env }` only — there is no `cwd` field". This is correct. The corresponding code comment in `agent.ts:111` cites a stale line number for the type definition (`sdk.d.ts:395`, actual location is `:1005`); the code reviewer flagged the same in `review-1.md`. T10 itself has no line cite, so it is unaffected.
